# Security

OpenAPI contracts are input data. They may come from third parties, from a server you do not control, or from a
pull request. BlazorApi treats them as untrusted: processing a contract must not exhaust resources, read files it
should not, or inject code into your build. This page describes the threats and the mitigations in the code.

## Threat model

| Threat | Where | Mitigation |
|---|---|---|
| Resource exhaustion by a huge or deeply nested document, or YAML alias expansion ("billion laughs") | parsers | `ParserLimits` |
| Reading arbitrary files through `$ref` (`../../secrets.yaml`, absolute paths) | reference resolution | reference policy and reference root |
| Server-side request forgery or network access through `$ref: https://...` | reference resolution | remote references disabled by default; built-in resolvers never download |
| Code injection through names, descriptions, enum values or patterns in the contract | code generation | identifier sanitization, literal and XML doc escaping, header sanitization, option validation |
| Writing or deleting files outside the output directory | CLI | output path containment, manifest-only deletion |
| Credential leakage | runtime | tokens in memory only, never logged or included in messages |
| Large or hostile error responses | runtime | error body size limit |
| Script injection through server error text in Blazor | components | text-only rendering |

## Parser limits

`ParserLimits` (namespace `BlazorApi.OpenApi.Syntax`, set through `OpenApiLoadOptions.Limits`):

| Limit | Default |
|---|---|
| `MaxDocumentLength` | 64 MiB of characters |
| `MaxDepth` | 256 nested objects and arrays |
| `MaxExpandedNodes` | 10,000,000 nodes, counting YAML aliases at every use |

`OpenApiLoadOptions.MaxExternalDocuments` (default 256) bounds the number of referenced documents. Exceeding a limit
reports BAPI1002. Recursive YAML aliases are rejected (BAPI1011). The parsers are hand-written and never execute
tags or construct arbitrary objects.

## References

- `ExternalReferencePolicy.LocalFiles` (the default) allows only files under the reference root. The root defaults
  to the directory of the root document; both the CLI and the source generator accept `references.root` in `blazorapi.json`. Paths are resolved
  as URIs and checked after normalization, so `..` segments cannot escape the root (BAPI2002).
- `http`/`https` references are rejected unless the policy is `LocalFilesAndRemote`; even then, the built-in
  file-system resolver (CLI) does not download anything, and the source generator only sees MSBuild AdditionalFiles.
  Other URI schemes are always rejected.
- `ExternalReferencePolicy.Disabled` allows only references inside the document.
- Hosts that need remote documents supply their own `IDocumentResolver`; it is then responsible for allow-listing
  hosts and limiting sizes.

## Generated source

The generated code is compiled into your application, so contract text must never become code.

- **Identifiers** (`Naming/Identifier.cs`): names are split into words at every non-alphanumeric character and
  rebuilt from letters and digits only; a leading digit gets `_`, C# keywords get `@`, and collisions get numeric
  suffixes. Quotes, braces, semicolons and comment markers cannot survive into an identifier.
- **String literals** (`CSharp/CodeWriter.cs`, `Literal.String`): every value from the contract that appears in code
  (paths, operation ids, parameter names, media types, discriminator and enum wire values, patterns, defaults) is
  emitted as an escaped C# string literal; quotes, backslashes, control characters and the line separators U+2028,
  U+2029 and U+0085 are escaped.
- **XML documentation** (`CodeWriter.Doc`): `&`, `<` and `>` are escaped, and every character C# treats as a line
  terminator becomes a new `///` line, so a description cannot end the comment.
- **File headers** (`CSharp/FileWriter.cs`): the API title and version in the `// <auto-generated>` header have
  control and line separator characters replaced with spaces.
- **Numbers**: integer enum values are emitted from parsed numbers, not from source text.
- **Options**: `namespace`, `modelsNamespace` and `clientName` must be valid C# names (BAPI5001).

`tests/BlazorApi.CodeGeneration.Tests/SecurityTests.cs` compiles a hostile contract (quotes, newlines, comment
terminators and line separators in titles, paths, operation ids, parameter names, patterns, schema names, enum values
and descriptions) and checks that no injected type exists.

## CLI file system access

- Every generated path is resolved against the output directory and rejected if it leaves it.
- Only files listed in the previous `.blazorapi-manifest` are deleted, and only when they are inside the output
  directory. Other files in the directory are never touched.
- `--dry-run` and `--check` never write.

## Runtime

- **Credentials** stay in memory: `CachingAccessTokenProvider` caches tokens in a dictionary and persists nothing.
  `AccessToken.ToString()` hides the value, and `ApiError.Message` never contains credentials.
- **Client credentials**: when the token endpoint rejects a request, `ClientCredentialsTokenSource` throws an
  `HttpRequestException` with the status only; the response body is not included because it may echo the secret.
- **Token refresh** retries a request at most once, and only when the body can be replayed.
- **Error bodies** are read up to `ApiClientOptions.MaxErrorBodyLength` characters (64 KiB by default) into
  `ApiError.Body`; truncated bodies are not deserialized.
- **Responses** are read from the stream with System.Text.Json and strict number handling; generated enum converters
  reject unknown values; polymorphic converters never instantiate types named by the payload (unknown discriminators
  become `Unrecognized*` types).
- **Blazor**: `ApiErrorView` and `ApiValidationErrors` render server-provided titles, details and field messages as
  text (Blazor encodes it), never as markup.

## Recommendations

- Review contract changes like code. Run `api-gen validate --strict` and `api-gen diff` in CI.
- Keep the default reference policy. Download remote documents in a controlled step and reference local copies.
- Prefer header API keys over query-string keys, which may appear in logs.
- Do not log `HttpRequestMessage` headers in custom `OnRequest` callbacks or handlers; they carry credentials.

To report a vulnerability, contact the maintainers privately through the repository's security advisory feature
rather than opening a public issue.
